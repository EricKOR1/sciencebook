# 문항 그림 보충 작업 지시 — 예제·바로 확인·확인 문제에 필요한 그림 넣기

너는 중학교부터 대학 1학년까지를 한 권으로 잇는 과학 교재 웹사이트 「한 권으로 잇는 과학」의 **문항 그림 담당**이다. 저장소는 /home/user/sciencebook 이다.

독자의 요청은 이렇다: "예제, 바로 확인, 실력 다지기, 도전 문항에서도 그림 자료가 필요하다면 넣어서 문항 설명을 보충해 달라."

지금 본문에는 그림이 충분하지만, **문항**(예제, 바로 확인, 개념 확인 문제의 기본·응용·융합·서술형·실력 다지기·도전)에는 그림이 거의 없다. 담당 단원의 문항을 하나하나 읽고, 그림이 있어야 상황이 분명해지는 문항에 그림(SVG)을 만들어 넣는다.

담당 단원의 파일은 저장소에서 `{단원 id}_` 로 시작하는 `.md` 이다.

## 먼저 읽을 것
1. `tools/authoring/VISUALS_GUIDE.md` 의 0~2절과 5절 — 그림(SVG) 제작 규칙과 확인 방법(시뮬레이션 부분은 읽지 않아도 된다). 그림 견본 파일도 읽는다. 색에 관해서는 아래 "꼭 지킬 것"이 우선한다.
2. 담당 단원 원고 전체와 이미 들어 있는 그림(`<!-- fig:이름 -->`, `docs/assets/fig/{id}-*.svg`). 본문 그림과 같은 내용을 문항에 또 그리지 않는다(바로 위·근처에 같은 그림이 있으면 "위 그림"으로 가리키면 된다).

## 어떤 문항에 그림을 넣나
문항을 읽으며 묻는다: **"글만 읽고 상황(배치·방향·모양·자료의 모양)을 틀림없이 떠올릴 수 있는가? 실제 시험지라면 그림이 붙었을 문항인가?"**

그림이 필요한 문항:
- **배치·방향이 답을 좌우하는 문항**: 빗면·도르래·충돌·원운동의 힘과 속도, 회로도(직렬·병렬, 계기의 위치), 전기장·자기장·전류의 방향, 광선과 거울·렌즈, 천체의 위치 관계, 지층 단면, 전선·기압 배치, 판의 경계
- **"그래프"·"자료"를 말하면서 표나 글로만 준 문항**: 그래프의 모양을 읽어야 하는 문항(가열 곡선, v–t, 반응 속도, 적정 곡선, 개체군 생장, 스펙트럼 등)은 실제 그래프를 준다. 값을 읽게 하려면 눈금을 넣는다.
- **구조에 기호를 붙여 묻는 문항**: "A~D의 이름", "(가)와 (나)를 비교" 같은 문항(세포·기관·분자 모형·실험 장치·가계도·염색체·지형)
- **실험 장치와 과정**: 장치의 연결, 변인을 다르게 한 여러 조건의 나란한 비교
- **지도가 필요한 문항**: 위치·경로·분포(기단, 해류, 태풍, 지진대 등) → 아래 "지도" 절대로
- **풀이에 그림이 있어야 이해되는 문항**: 자유 물체 도형, 벡터 합성, 작도, 그래프 위의 넓이·접선 → 이런 그림은 **정답·해설(`<details>`) 안**에 넣는다.

넣지 않는 문항: 용어·정의를 묻는 문항, 계산만 하는 문항, 글과 표로 충분한 문항, 본문 그림을 그대로 가리키면 되는 문항. **꾸미기용 그림은 만들지 않는다.**

분량: 단원마다 보통 **4~8개**(문항이 그림과 거리가 먼 단원은 2~3개, 역학·전자기·광학·지구과학·구조를 다루는 생명과학 단원은 많아질 수 있다. 10개를 넘기지 않는다). 예제, 바로 확인, 기존 문제(기본·응용·융합·서술형), 실력 다지기, 도전을 **고루** 살핀다.

## 문항 그림이 지켜야 할 것 (본문 그림과 다른 점)
1. **정답을 드러내지 않는다.** 묻는 대상에는 이름 대신 기호(A, B, (가), (나), ㉠)를 붙인다. 구해야 하는 값·방향·이름을 그림이나 그림 설명에 적지 않는다.
   - 사이트는 SVG의 `<title>` 과 `<desc>` 를 그림 아래에 **그대로 보여 준다.** 문항(문제 쪽) 그림의 `<desc>` 에는 문제에 주어진 것만 쓴다(예: "빗면 위에 놓인 물체와 줄, 도르래의 배치. 각과 질량은 문제에 주어진 값이다."). 정답·해설 안에 넣는 그림에는 풀이 내용을 써도 된다.
2. **문제의 수치·조건과 정확히 일치**시킨다(각도, 길이 비, 개수, 눈금, 방향, 기호). 그래프의 점·곡선은 python으로 계산한 좌표로 그린다. 힘·속도 화살표의 길이는 크기에 비례하게 한다(비례가 아니면 "길이는 크기와 무관"이라고 적는다).
3. 제목은 `그림 {표시 번호}-{n} …` 형식(예: `그림 3-4-9 문제 12의 실험 장치`, `그림 중2-3-8 예제 3의 광선`). 번호는 기존 그림 뒤로 이어 붙이면 된다(조율자가 순서대로 다시 매긴다). 파일 이름은 `{단원 id}-q-{영문-설명}.svg` (문항 그림임을 알 수 있게 `-q-` 를 넣는다. 예: `3-4-q-cart-collision.svg`).
4. 문항 글에서 그림을 가리킨다: "그림과 같이", "아래 그림은 …을 나타낸 것이다", "위 그림의 A는". **그림 번호("그림 3-4-9")로 가리키지 않는다.** 이를 위해 문항의 첫 문장을 조금 고치는 것은 허용한다(뜻·수치·정답은 바꾸지 않는다). 그림에 기호를 붙였으면 문항 글도 그 기호에 맞춘다.

## 표식을 넣는 자리 (형식)
표식은 `<!-- fig:이름 -->` 한 줄 단독, 앞뒤 빈 줄, **줄 맨 앞에서 시작**(들여쓰기 금지).
- **예제**: 문제 글 바로 뒤, `**풀이**` 앞. 풀이용 그림은 풀이 글 안의 알맞은 곳.
- **바로 확인**: 번호 목록 사이에 넣으면 목록이 끊긴다. `#### ✔ 바로 확인` 제목 바로 아래(목록 앞)에 넣고, 해당 번호 문항에서 "위 그림에서 …"로 가리킨다. 한 블록에 그림은 1개까지.
- **개념 확인 문제**: `**12.** …` 문제 글 뒤, `<details>` 앞(빈 줄로 구분). 해설용 그림은 `<details>` 안, `<summary>` 다음 글 사이에 넣는다(`</details>` 앞 빈 줄 유지).
- 문제 번호·예제 번호·정답은 바꾸지 않는다. 문항을 새로 만들거나 지우지 않는다.

## 그림 제작에서 꼭 지킬 것 (지난 검토에서 자주 나온 잘못)
- CSS 클래스 이름은 **글자로 시작**한다. 단원 id가 숫자로 시작하면(`3-4-…`) 클래스 앞에 `f` 를 붙인다(`.f3-4-q-cart-lbl`). 숫자로 시작하는 클래스는 스타일이 통째로 무시된다.
- 속성 이름·값에 유니코드 마이너스(−)를 쓰지 않는다(`text-anchor`, `class` 등은 반드시 하이픈 `-`). 생성 스크립트에서 문자열 치환으로 하이픈이 바뀌지 않게 주의한다.
- 모든 글자·도형은 `viewBox` 안에 있어야 한다(오른쪽·아래 끝 잘림 주의). 글자 13~15px.
- **크기**: 사이트는 그림을 칸 너비에 맞춰 늘린다. 물체 하나, 회로 하나처럼 **간단한 그림**은 `viewBox` 너비를 420~480으로 잡고 루트에 `class="fig-small"` 을 붙인다(`<svg … viewBox="0 0 460 260" class="fig-small" …>`). 그러면 480px보다 커지지 않고 휴대폰에서는 화면에 맞게 줄어든다. 여러 칸을 나란히 비교하는 그림과 눈금을 읽는 그래프는 너비 720으로 그린다.
- **지시선·지시점은 가리키는 구조의 안쪽**에 닿게 한다. 이름표가 선·곡선·다른 글자와 겹치지 않게 한다.
- 방향을 틀리기 쉬운 것은 다시 확인한다: 오른손 법칙(전류·자기장·힘), 공전·자전 방향과 속도 화살표, 동서남북(하늘 그림은 동서가 지도와 반대), 배사(위로 볼록)·향사(아래로 볼록), 정단층·역단층의 상반, DNA는 오른손 나선, 5′·3′ 방향, 심장의 좌우, 물관(안쪽)·체관(바깥쪽), 전지의 (+)(−)극과 전자 이동 방향, 북반구 고기압(시계 방향으로 불어 나감)·저기압.
- 입자 모형은 **개수·전하 균형**을 맞춘다. 평형 그림의 양쪽 화살표 수, 반응 전후 원자 수를 센다.
- 색은 토큰(`var(--fig-…)`)을 쓴다. 검은 잉크·흰 배·해·불꽃처럼 **색 자체가 뜻인 것**은 고정색을 쓰고 테두리를 넣어 어두운 화면에서도 보이게 한다. `--fig-ink` 로 칠한 넓은 면은 어두운 화면에서 밝게 뒤집힌다.
- **지도**는 손으로 그리지 말고 `tools/authoring/basemap.mjs` 를 쓴다(맨 위 주석에 사용법). 우리나라 주변은 `--res 50m`(10m 는 좁은 범위에서 육지·바다가 뒤집히는 일이 있다), 세계는 `--res 110m`. 위치는 경위도로 정해 `--points`, `--lines` 로 변환한다. 지명은 교과서 표기(동해, 황해(서해), 독도).

## 지킬 것
- 고칠 수 있는 것: 담당 단원 원고에 표식 넣기와, 그림을 가리키기 위한 문항 글의 **최소 수정**. 그 밖의 본문·해설·수치·번호는 건드리지 않는다. 문항에서 명백한 오류를 발견하면 고치지 말고 보고에 적는다.
- `tools/` 아래 공통 파일, `docs/assets/js/book.js`, `docs/assets/book.css`, 다른 담당의 파일은 수정하지 않는다. 전체 빌드와 git 커밋·푸시를 하지 않는다.
- 확인용·생성용 파일은 scratchpad 안의 **네 전용 폴더**(작업 지시에 적힌 이름)에만 둔다:
  `/tmp/claude-0/-home-user-sciencebook/96b7e817-0e5e-5324-8416-180ac4e267af/scratchpad/<전용 폴더>/` (없으면 mkdir -p). 저장소 안에 확인용 파일을 만들지 않는다.
