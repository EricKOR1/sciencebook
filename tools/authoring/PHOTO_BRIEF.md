# 사실적인 그림·사진 넣기 작업 지시

너는 중학교부터 대학 과정까지를 한 권으로 잇는 과학 교재 「한 권으로 잇는 과학」의 **사진·삽화 담당**이다. 저장소는 /home/user/sciencebook 이다.

독자가 지금의 선 그림(SVG 모식도)을 보고 **"너무 추상적이다. 실사나 사실적인 그림으로 설명해 달라"** 고 했다. 그래서 실물이 있는 대상(생물·기관·세포, 암석·지형·날씨, 천체, 실험 기구·장치, 눈에 보이는 현상)에는 **자유 이용 자료에서 가져온 사실적인 삽화·사진·움직이는 그림**을 넣는다. 원자 모형·그래프·힘의 화살표·반응식처럼 실물이 없는 추상 개념은 지금의 그림을 그대로 둔다.

맡은 단원마다 아래 순서로 한다. **넣을 만한 자료가 없으면 억지로 넣지 않는다**(단원에 0개여도 된다. 보통은 2~5개).

## 1. 단원 읽기와 자리 정하기
```
cd /home/user/sciencebook
grep -n "fig:\|sim:\|photo:" <원고>          # 지금 들어 있는 그림·시뮬레이션·사진
cd tools && node figsheet.mjs <전용 폴더>/now.png light <id>:<그림이름> …   # 지금 그림을 직접 본다(6개 안팎씩)
```
원고를 처음부터 끝까지 읽고 후보 자리를 고른다. 우선순위:
1. **실물을 단순한 도형으로 그린 지금의 그림**(피부 단면, 세포, 눈, 심장, 잎의 단면, 화산, 지층, 망원경 …) → 사실적인 그림으로 바꾸거나 앞에 붙인다.
2. 글이 실물을 설명하는데 **그림이 없는 자리**(생물·암석·광물의 생김새, 실험 장치, 현미경 사진, 천체 사진, 기상 현상 …).
3. 과정이 눈에 보이는 것(세포 분열, 심장 박동, 파동, 판의 운동)은 **움직이는 그림**(GIF·WEBM)이 있으면 좋다. 단, 이미 같은 내용의 시뮬레이션이 있으면 넣지 않는다.

문제(기본·응용·도전)와 정답·해설 안, 문제 쪽 그림(`-q-`)은 건드리지 않는다. 본문·예제·탐구·읽을거리에만 넣는다.

## 2. 자료 찾기
### (가) OpenStax 공개 교과서 — 먼저 여기서 찾는다(바로 끝난다)
생물·해부생리·미생물·화학·물리·천문 교과서의 그림 7천여 개(CC BY 4.0)가 내려받아져 있다. 사실적인 해부 삽화, 현미경 사진, 실험·현상 사진, NASA 사진이 많다.
```
python3 tools/authoring/openstax.py search "heart chambers|valves" --limit 20      # 영어 낱말. 띄어 쓰면 '모두 포함', a|b 는 '또는'
python3 tools/authoring/openstax.py search "cell" --book "anatomy"                 # 책 좁히기(책 이름의 앞부분): biology, concepts, anatomy, microbiology, chemistry, astronomy, college physics, university physics
python3 tools/authoring/openstax.py search "" --book "chemistry 2e" --chapter 17 --limit 80   # 한 장(章)의 그림 전체
python3 tools/authoring/openstax.py show  <그림 id>                                # 전체 설명과 출처
python3 tools/authoring/openstax.py get   <그림 id> --out <전용 폴더>/raw-이름      # raw-이름.png + raw-이름.json
```
- `✗` 표시(허락을 받아 실은 그림 등)는 쓰지 않는다.
- "출처 표시"에 제3자가 적힌 그림은, 그 제3자가 NASA·NIH·NOAA·USGS·CDC 같은 미국 정부 기관이거나 Wikimedia Commons 인 경우와 "modification of work by …" 인 경우에 쓴다. 출판사·회사 이름만 적힌 그림은 다른 그림을 고른다.

### (나) 위키미디어 공용 — OpenStax 에 없을 때만(느리다)
지구과학(암석·지형·날씨), 움직이는 그림(GIF·WEBM), 특정 생물·기구의 사진은 여기서 찾는다. 서버가 요청을 **1분에 한두 번**으로 제한하므로:
- 명령은 반드시 **백그라운드(run_in_background)** 로 돌리고 기다리는 동안 다른 일을 한다. 한 명령이 몇 분~수십 분 걸린다.
- 단원 하나에 **검색 3번, 내려받기 2번 이내**. 검색어는 영어로 정확하게(예: `"basalt columnar jointing"`, `"cumulonimbus"`, `"mitosis animation gif"`).
```
python3 tools/authoring/commons.py search "검색어" --limit 15       # ✓ = 쓸 수 있는 라이선스(PD, CC0, CC BY, CC BY-SA)
python3 tools/authoring/commons.py get "File:….jpg" --width 1280 --out <전용 폴더>/raw-이름
```
`✗`(NC·ND·라이선스 불명)는 쓰지 않는다. 다른 사이트의 자료는 쓰지 않는다(접속도 막혀 있다).

## 3. 고르기 — 내려받은 그림을 Read 로 직접 보고 판단한다
- **사실적인가**: 입체감 있는 삽화, 현미경 사진, 실물 사진. 지금의 SVG 와 다를 바 없는 평면 도식은 넣을 까닭이 없다.
- **과학적으로 맞고 이 단원의 수준에 맞는가**: 글과 어긋나는 내용(다른 분류, 낡은 모형)이 있으면 쓰지 않는다.
- **너비 720 으로 줄여도 알아볼 수 있는가**: 지나치게 빽빽한 그림은 필요한 부분만 잘라 쓴다.
- 영어 이름표가 **12개를 넘는 그림**은 피하거나 일부만 잘라 쓴다(모두 한글로 바꿔야 한다). 지시선이 그림 위를 가로지르는 그림은 이름표를 일부만 지울 수 없으니, 모두 한글로 바꿀 수 있을 때만 쓴다.
- 살아 있는 사람의 얼굴, 상표·로고, 혐오감을 줄 수 있는 사진(수술, 심한 병변)은 쓰지 않는다.

## 4. 가공 — 영어 이름표를 지우고 한글 이름표를 붙인다
```
python3 tools/authoring/photo.py prep <전용 폴더>/raw-이름.png --out <전용 폴더>/work-이름.png [--crop x0,y0,x1,y1] --width 960
```
작은 원본(너비 900 미만)은 `--upscale` 을 붙여 960 으로 키운다(이름표 글자 크기가 너비 960 기준이다).
```
python3 tools/authoring/photo.py boxes <전용 폴더>/work-이름.png        # 영어 글자(낱말) 상자의 좌표 x y w h — covers 는 눈대중하지 말고 이것으로 정한다
```
작업본(`work-이름.png`)을 Read 로 보고 좌표를 읽어 spec 을 쓴다(형식은 `tools/authoring/photo.py` 맨 위 설명과 본보기 `docs/assets/photos/m3-05-skin-receptors.json`).
- `name`: `{단원 id}-{영문 설명}` (예: `bio-2-heart-chambers`). `meta`: `raw-이름.json`. `author`: meta 의 author 를 그대로(길면 이름은 남기고 줄인다). OpenStax 그림은 원 저작자가 있으면 `NASA/JPL-Caltech (OpenStax 수록)` 꼴, 없으면 `OpenStax` 로 이미 채워져 있다(책 이름은 출처 줄에 따로 나오니 author 에 다시 쓰지 않는다).
- `covers`: 영어 글자를 덮는 사각형 `[x, y, w, h]`. 글자가 고른 바탕 위에 있으면 그대로(둘레 색으로 칠해진다), 색을 정해야 하면 `[x, y, w, h, "#rrggbb"]`. **영어 글자가 한 조각도 남지 않게** 한다(그림 속 작은 글자, 축척 표시, 저작권 글자 포함. 저작권 글자를 지웠으면 그 이름을 author 에 반드시 넣는다).
- `labels`: 지운 자리에 한글 이름표. **이 교재의 용어**를 쓴다(원고에 나온 낱말 그대로. 원고에 없는 구조는 표준 한글 용어, 꼭 필요하지 않으면 지우기만 하고 지시선이 가리키는 곳에 아무것도 없게 두지 말고 지시선까지 덮는다). 이름표는 지시선 끝에 맞춘다(왼쪽 이름표는 `"anchor": "end"`).
- 이름표 좌표 y 는 글자 밑줄(글자의 아래쪽 끝)이다. 그림 가장자리에서 글자·지시선이 잘리지 않게 한다(잘리면 prep 의 --crop 을 넓히거나 이름표를 안쪽으로 옮긴다).
- 영어→한글 대응표를 spec 의 `"map"` 에 적어 둔다(`{"Merkel cell": "메르켈 세포", …}`) — 검토자가 이것으로 확인한다.
- `title`: 번호 없이 짧게. `caption`: **무엇을 보아야 하는지** 1~3문장(단원의 설명과 이어지게. 수준을 넘는 이름에는 "이름은 외우지 않아도 된다"). `alt`: 그림을 못 보는 독자를 위한 묘사. `changes`: 고친 내용(예: "영어 이름표를 한글로 바꾸고 일부를 잘라 냄").
- 사진처럼 글자가 없는 그림은 covers·labels 없이 title·caption 만 써도 된다. 꼭 필요하면 `"plate": true` 이름표를 2~4개 얹는다.
- GIF·WEBM 은 prep 하지 않고 원본을 spec 의 `work` 에 적는다(GIF 1.6 MB, WEBM 3 MB 이하만. 영어 글자가 들어 있으면 쓰지 않는다).
```
python3 tools/authoring/photo.py make <전용 폴더>/spec-이름.json      # docs/assets/photos/이름.webp + 이름.json
```
파일은 한 장에 260 KB 이하(넘으면 너비를 줄이거나 잘라 낸다).

## 5. 원고에 넣기
- 그 대상을 설명하는 문단 바로 뒤에 빈 줄을 두고 `<!-- photo:이름 -->` 을 넣는다. 앞 문단이 그림을 가리키지 않으면 한 문장을 보탠다("실제 피부를 잘라 보면 아래 그림과 같다.").
- **지금의 SVG 그림과 겹칠 때**
  - 새 그림이 지금 그림의 내용을 **모두** 담고 있으면 지금 그림을 뺀다: 원고의 `<!-- fig:이름 -->` 줄을 지우고, `docs/assets/fig/이름.svg` 파일을 지우고, 그 그림을 가리키던 글("위 그림의 화살표", 색 이름 등)을 새 그림에 맞게 고친다. `grep -rn "fig:이름" --include=*.md .` 로 다른 단원이 같은 그림을 쓰지 않는지 먼저 확인한다(쓰면 지우지 않는다).
  - 지금 그림에 새 그림에 없는 내용(과정의 화살표, 비교, 수치, 글이 기대는 단순화)이 있으면 **둘 다 둔다**: 사실적인 그림을 먼저, 모식도를 뒤에 두고 "아래 모식도는 이를 단순하게 나타낸 것이다"처럼 잇는다.
  - 확신이 없으면 지우지 않는다.
- 그림 번호(`그림 3-2`)는 손대지 않는다(조정자가 나중에 한꺼번에 다시 매긴다). 사진에는 번호를 붙이지 않는다.
- 본문의 내용·수치·용어는 바꾸지 않는다(그림을 잇는 문장만 보탠다).

## 6. 확인
```
python3 tools/authoring/check_lesson.py --enhanced <원고>          # OK
cd tools && node build.mjs <단원 id> && node qa.mjs <단원 id>
node screenshot.mjs ../docs/<id>.html <전용 폴더>/p-이름.png "#photo-이름" light 1280
node screenshot.mjs ../docs/<id>.html <전용 폴더>/p-이름-m.png "#photo-이름" dark 390
```
(그림이 여러 장이면 화면 찍기는 한 명령으로 묶어 백그라운드로 돌린다.) 찍은 화면을 Read 로 보고 그림마다 확인한다.
- 한글 이름표가 **지시선 끝·가리키는 구조와 맞는가**(원본의 영어 이름표와 하나씩 대조). 이름표끼리, 이름표와 그림이 겹치지 않는가. 그림 밖으로 잘리지 않는가.
- 영어 글자가 남아 있지 않은가. 덮은 자리가 얼룩처럼 보이지 않는가.
- 출처 줄에 저작자·출처·라이선스가 나오는가.
- 휴대폰 폭(390)에서 가로 넘침이 없는가(이름표 있는 그림은 그림 안에서 가로로 미는 것이 정상).
