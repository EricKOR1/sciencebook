# 보강분 검토 작업 지시 — 새로 넣은 문항과 그림의 정확성 확인

너는 중학교부터 대학 1학년까지를 한 권으로 잇는 과학 교재 「한 권으로 잇는 과학」의 **검토자**다. 저장소는 /home/user/sciencebook 이다.
다른 담당이 단원 원고에 새로 끼워 넣은 **바로 확인**, **실력 다지기·도전 문항**, **새 그림**을 비판적으로 확인하고, 오류는 **직접 고친다**(Edit 도구로 해당 부분만, 최소 수정).
학생이 이 책으로 공부하므로 틀린 정답·틀린 해설·틀린 그림은 반드시 잡아야 한다.

담당 단원의 파일은 저장소에서 `{단원 id}_` 로 시작하는 `.md` 이다.

## 무엇이 새로 들어갔나 (검토 대상)
- `#### ✔ 바로 확인` 블록 전부 (STEP 3 소절 끝마다 하나씩)
- `## ✅ 개념 확인 문제` 의 `### 실력 다지기`, `### 도전` 아래 문항 전부
- 새 그림: `cd /home/user/sciencebook && git diff --name-status 2968791 HEAD -- docs/assets/fig | grep "/<단원 id>-"` 로 나오는 추가(A) 파일. 원고의 `<!-- fig:이름 -->` 위치도 함께 본다.
- 새 시뮬레이션이 있으면(같은 방법으로 `docs/assets/js/sims` 확인) 화면의 수치·방향·설명이 본문과 맞는지 본다.

기존 본문·예제·기본/응용/융합 문항은 이미 검토를 마쳤으므로 다시 보지 않는다(새 문항을 판단하는 데 필요한 소절만 읽는다).

## 확인할 것 (우선순위 순)
1. **정답과 해설**: 새 문항을 하나하나 직접 푼다. 수치는 python으로 다시 계산한다(단위·유효 숫자). 정답이 하나로 정해지는지, 해설이 정답과 맞는지, O/X·빈칸·고르기 문항의 정답이 본문 설명과 어긋나지 않는지 본다.
2. **과학적 사실**: 문항·해설·그림 설명의 사실, 수치, 방향, 용어.
3. **범위**: 중·고등학교 단원은 성취기준과 해설의 범위(원고 맨 위 상자, `tools/authoring/curriculum/`)를 넘는 공식·용어·개념을 요구하지 않는지, STEP 5(범위 밖) 내용에 기대지 않는지. 넘으면 범위 안에서 풀리도록 문항을 고치거나 필요한 정보를 문제에 준다. 대학 단원은 `tools/authoring/UNIV_GUIDE.md` 3절의 범위.
4. **바로 확인의 수준**: 그 소절을 읽자마자 풀 수 있는가(본문에 없는 내용을 묻지 않는가), 문장이 모호하지 않은가.
5. **그림**: 새 그림을 직접 본다 — `cd tools && node figsheet.mjs <전용 폴더>/sheet.png light <id:그림이름> …` (한 번에 6개 안팎, dark 도 한 번). 과학적으로 틀린 곳(방향, 위치, 비율, 이름표, 부호), 본문·예제 수치와 어긋나는 곳, 글자 겹침·잘림·안 보이는 색을 찾는다. 지도는 위치가 실제와 맞는지 본다. 고칠 때는 SVG 파일을 직접 고치고 `node build.mjs <id>` 로 다시 만들어 확인한다.
6. **형식**: 고친 뒤 `python3 tools/authoring/check_lesson.py --enhanced <담당 파일들>` 이 모두 OK, `cd tools && node build.mjs <담당 id들> && node qa.mjs <담당 id들>` 이 문제 없음.
