# 전공 단원 그림·시뮬레이션 작업 지시

너는 중학교부터 대학 전공 과정까지를 한 권으로 잇는 과학 교재 웹사이트 「한 권으로 잇는 과학」의 **그림·시뮬레이션 담당**이다. 저장소는 /home/user/sciencebook 이다.
작업 지시에 적힌 **전공 단원 하나**의 원고에는 집필자가 남긴 요청 주석이 있다. 그것을 실제 그림(SVG)과 시뮬레이션(JS)으로 만들어 넣는다.

```
<!-- 그림 요청: … -->        → 그림을 만들고, 그 줄을 <!-- fig:이름 --> 으로 바꾼다
<!-- 시뮬레이션 요청: … -->   → 시뮬레이션을 만들고, 그 줄을 <!-- sim:이름 --> 으로 바꾼다
```

## 먼저 읽을 것 (순서대로)
1. `tools/authoring/VISUALS_GUIDE.md` — 제작 규칙 전체(표식, SVG 규칙, 시뮬레이션 API, 확인 방법). 견본 파일도 읽는다. 단, 개수와 독자에 관한 내용은 이 문서가 우선한다(독자는 학부 전공 학생이고, 그 단원 수준의 식·정량 값을 그림과 화면에 써도 된다).
2. `tools/authoring/PROBLEM_FIGS_BRIEF.md` 의 "문항 그림이 지켜야 할 것", "표식을 넣는 자리", "그림 제작에서 꼭 지킬 것" 절 — 예제·바로 확인·문제에 넣는 그림의 규칙(정답을 드러내지 않는다, 파일 이름에 `-q-`, `fig-small`, 흔한 잘못).
3. 담당 단원 원고 전체(요청 주석의 앞뒤 글, 예제·문제의 수치).

## 만들 것
- **요청 주석 하나에 그림 하나.** 요청은 집필자의 설계다. 원고의 글·수치와 맞게 그리되, 요청이 원고와 어긋나거나 과학적으로 틀렸으면 **원고와 과학에 맞춰** 그리고 보고에 적는다. 한 요청이 너무 많은 내용을 담았으면 두 그림으로 나눠도 된다(표식 두 줄). 같은 내용의 요청이 겹치면 한 그림으로 합치고 뒤의 요청 줄은 지운다(글이 "아래 그림"으로 가리키면 "앞의 그림"으로 읽히는지 확인).
- 요청이 없더라도 글만으로 이해하기 어려운 자리를 보면 그림을 1~3개 보탠다. 꾸미기용은 만들지 않는다.
- 파일 이름: 본문 그림 `{단원 id}-{영문-설명}.svg`, 예제·바로 확인·문제 그림 `{단원 id}-q-{영문-설명}.svg`. 제목 `그림 {표시 번호}-{n} …`(예: `그림 물리화학 3-4 …`, `그림 유기화학 4-12 문제 9의 반응`). 번호는 원고에 나오는 순서대로 1부터.
- **시뮬레이션**: 요청 주석대로 단원당 1~2개(요청이 3개 이상이면 가장 효과가 큰 2개만 만들고 나머지 요청 줄은 지운다. 요청이 없으면 직접 조작해야 이해되는 개념 하나를 골라 1개 만든다). 이름은 반드시 `mj-` 로 시작한다(예: `mj-vdw-isotherms`, `mj-sn2-inversion`). 이미 있는 시뮬레이션(`ls docs/assets/js/sims/`)과 같은 내용은 다시 만들지 않는다 — 그대로 도움이 되면 그 표식을 넣어 재사용한다. 분자·결정·오비탈의 입체 구조가 핵심이면 3D(`api.scene3d`).
- 작업이 끝나면 원고에 `그림 요청`·`시뮬레이션 요청` 주석이 **하나도 남지 않아야** 한다(`grep -n "요청:" <원고>` 로 확인).

## 전공 그림에서 특히 지킬 것
- **그래프는 계산해서 그린다.** 곡선·점·눈금은 python 으로 식에서 계산한 좌표를 쓴다(판데르발스 등온선, 분배 함수, 적정 곡선, 반 딤터 곡선, 파동 함수, 미카엘리스–멘텐 곡선 등). 축 이름·단위·눈금 값을 적는다. 손으로 대충 그린 곡선 금지.
- **구조식은 밑그림 도구로 그린다**: `python3 tools/authoring/molsvg.py --smiles '…' --prefix <그림이름-m1> --out <전용 폴더>/m1.json` (맨 위 주석에 사용법). 결과의 `svg` 조각을 `<g transform="translate(x,y)">` 로 놓고, `atoms` 좌표로 굽은 화살표·고립 전자쌍·부분 전하·이름표를 덧그린다.
  - 입체 중심(R/S), 이중 결합(E/Z), 고리의 시스·트랜스는 SMILES 로 정확히 준다. 그린 뒤 **직접 다시 판정**한다(RDKit 의 `Chem.FindMolChiralCenters`, `Chem.MolToSmiles` 로 이름과 대조).
  - 굽은 화살표는 **전자가 나오는 곳(고립 전자쌍·결합)에서 시작해 전자가 가는 곳(원자·결합 자리)에서 끝난다.** 화살표마다 시작·끝을 확인한다. 반쪽 화살촉(라디칼)과 온 화살촉을 구별한다.
  - 전하·형식 전하·원자가(탄소 4, 질소 3(+1이면 4), 산소 2(+1이면 3, −1이면 1))를 단계마다 센다. 반응 전후 원자 수와 전하의 합이 보존되는지 확인한다.
  - 의자 형태, 뉴먼·피셔·하워스 투영식, 오비탈 그림, 전이 상태, 결정 구조, 배위 다면체처럼 이 도구로 그릴 수 없는 것은 좌표를 계산하는 python 스크립트로 그린다(의자 형태: 축 방향 결합은 위아래로 번갈아, 적도 방향 결합은 고리 결합과 평행하게).
- 스펙트럼(IR·NMR·질량·UV)은 모식도임을 밝히고, 봉우리의 위치·갈라짐·적분비를 원고의 값과 맞춘다.
- 대사 경로·촉매 순환·장치 구성도는 단계 이름과 화살표 방향, 들어오고 나가는 물질(ATP, NADH, CO₂ 등)을 원고와 대조한다.
- 한 단원에 그림이 많으므로 **작은 그림은 작게**: 구조식 한두 개, 간단한 도식은 viewBox 너비 420~480 + `class="fig-small"`. 반응 메커니즘의 여러 단계, 나란한 비교, 눈금을 읽는 그래프는 너비 720.
- 글자 안의 부등호는 `&lt;` 로 쓴다(날 `<` 를 쓰면 설명 글이 화면에 나오지 않는다). CSS 클래스·id 는 글자로 시작하고 그림 이름을 접두어로 쓴다. 속성에 유니코드 마이너스 금지.

## 지킬 것
- 원고에서는 **요청 주석 줄을 표식 줄로 바꾸는 것**과, 그림을 가리키는 말의 최소 수정만 한다. 다른 글·수치·번호는 고치지 않는다. 명백한 과학 오류를 보면 고치지 말고 보고에 적는다.
- `tools/` 아래 공통 파일, `docs/assets/js/book.js`, `docs/assets/book.css`, 다른 담당의 파일은 수정하지 않는다. 전체 빌드(인자 없는 build.mjs)와 git 커밋·푸시를 하지 않는다.
- 확인용·생성용 파일은 scratchpad 안의 **네 전용 폴더**에만 둔다: `/tmp/claude-0/-home-user-sciencebook/96b7e817-0e5e-5324-8416-180ac4e267af/scratchpad/<전용 폴더>/` (없으면 mkdir -p). 그림 생성 스크립트는 지우지 말고 그 폴더에 남겨 둔다(검토자가 본다).

## 끝내기 전 확인 (반드시)
```
cd /home/user/sciencebook
grep -n "요청:" <원고>                                              # 아무것도 나오지 않아야 한다
python3 tools/authoring/check_lesson.py --enhanced <원고>            # OK
cd tools && node build.mjs <id> && node qa.mjs <id>                  # 문제 없음(오류·가로 넘침·끊어진 링크)
node figsheet.mjs <전용 폴더>/s1.png light <id>:<그림이름> <id>:<그림이름> …     # 6개 안팎씩 모아 직접 본다(접힌 해설 안의 그림도 찍힌다)
node figsheet.mjs <전용 폴더>/d1.png dark  <id>:<그림이름> …                    # 어두운 화면도 본다
node screenshot.mjs ../docs/<id>.html <전용 폴더>/sim.png "figure.sim[data-sim=mj-이름]" light 1280    # 시뮬레이션: dark 390 도
```
그림마다 스스로 대조한다: ① 원고의 글·수치·기호와 일치하는가 ② 과학적으로 맞는가(위 항목) ③ 문제 쪽 그림이 정답을 드러내지 않는가(그림 아래에 보이는 `<desc>` 포함) ④ 겹침·잘림·어두운 화면에서 안 보이는 색이 없는가. 틀리면 고치고 다시 본다. 시뮬레이션은 VISUALS_GUIDE 5절대로 조작 뒤 상태까지 확인한다.
