# 전공 단원 그림·시뮬레이션 검토 작업 지시

너는 중학교부터 대학 전공 과정까지를 한 권으로 잇는 과학 교재 「한 권으로 잇는 과학」의 **검토자**다. 저장소는 /home/user/sciencebook 이다.
다른 담당이 **전공 단원**에 넣은 그림(SVG)과 시뮬레이션(JS)을 비판적으로 확인하고, 잘못은 **직접 고친다**(해당 부분만, 최소 수정). 학생이 이 그림으로 구조·메커니즘·그래프를 배우므로, 틀린 그림은 틀린 글보다 해롭다. 오류가 **있다고 가정하고** 찾는다.

## 먼저 읽을 것
1. `tools/authoring/MAJOR_VISUALS_BRIEF.md` — 그림 담당이 받은 지시(특히 "전공 그림에서 특히 지킬 것").
2. `tools/authoring/PROBLEM_FIGS_REVIEW_BRIEF.md` 의 "확인할 것" — 문항 그림(`-q-`) 확인 항목.

## 검토 대상
```
cd /home/user/sciencebook
grep -n "fig:\|sim:" <원고>              # 원고에 들어간 자리(순서)
ls docs/assets/fig | grep "^<id>-"       # 그림 파일
ls <그림 담당의 전용 폴더>                # 생성 스크립트(좌표·SMILES 를 여기서 확인한다)
```
그림마다 그 그림이 붙은 글(본문 소절, 예제, 문제와 해설)을 함께 읽는다.

## 확인할 것 (우선순위 순)
1. **과학적으로 맞는가**
   - 그래프: SVG 좌표를 읽어 값으로 되돌리고, 식으로 다시 계산해 대조한다(축 눈금 → 값). 곡선의 모양·극값·절편·점근선, 축 이름과 단위.
   - 구조식: 원자가(C 4, N 3, O 2 …)와 형식 전하, 수소 수, 고리 크기, 치환 위치를 센다. 입체 중심의 R/S, 이중 결합의 E/Z, 시스·트랜스, 축·적도 방향을 **직접 판정**해 이름과 대조한다(생성 스크립트의 SMILES 를 RDKit 으로 다시 확인).
   - 메커니즘: 굽은 화살표가 전자가 나오는 곳에서 시작해 가는 곳에서 끝나는가. 단계마다 원자 수·전하 합이 보존되는가. 중간체·전이 상태·생성물이 원고와 같은가(위치·입체 선택성 포함).
   - 무기: 점군과 대칭 요소, d 오비탈 갈라짐의 순서, 배위 구조와 이성질체, 단위 세포의 원자 수·배위수. 분석: 장치 구성의 순서, 곡선의 당량점·봉우리 위치. 생화학: 경로의 순서·효소·출입 물질, 구조(아미노산, 당, 뉴클레오타이드)의 원자와 입체 배치, 막·단백질 모식의 방향(N→C, 5′→3′).
2. **원고와 일치하는가**: 수치·기호·이름표·단계 번호가 글·표·해설과 같은가. 글이 "아래 그림"으로 가리키는 자리에 그 그림이 있는가.
3. **문항 그림이 정답을 드러내지 않는가**(그림 아래에 보이는 `<title>`·`<desc>` 포함). 정답·해설 안의 그림은 답을 보여도 된다.
4. **보기**: `cd tools && node figsheet.mjs <전용 폴더>/s.png light <id>:<그림이름> …`(6개 안팎씩)과 dark 로 모두 본다. 글자 겹침·잘림, 지시선이 엉뚱한 곳을 가리키는 것, 어두운 화면에서 안 보이는 색, 지나치게 큰 글자(간단한 그림이 720 너비로 늘어난 경우 `fig-small`).
5. **시뮬레이션**: 코드를 읽어 식·단위·상수를 확인하고, `node screenshot.mjs ../docs/<id>.html <전용 폴더>/sim.png "figure.sim[data-sim=이름]" light 1280` 과 `dark 390` 으로 본다. 슬라이더를 끝값으로 옮겼을 때 화면이 깨지지 않는지(값이 무한대·음수가 되는 구간), caption 의 설명이 화면과 맞는지 본다.
6. **형식**: 원고에 `요청:` 주석이 남아 있지 않은가(`grep -n "요청:" <원고>`). 날 부등호 `<` 가 SVG 글자에 없는가, 클래스 이름이 글자로 시작하는가. 고친 뒤 `python3 tools/authoring/check_lesson.py --enhanced <원고>` OK, `cd tools && node build.mjs <id들> && node qa.mjs <id들>` 문제 없음.

## 작업 원칙
- 최소 수정. 맞는 그림은 건드리지 않는다. 그림이 원고와 어긋나면 **그림을 원고에 맞춘다**. 원고가 명백히 틀렸으면 원고의 그 부분도 고치고 보고에 적는다(수치·정답이 바뀌면 관련된 곳을 모두 맞춘다).
- 고칠 수 없을 만큼 틀린 그림은 생성 스크립트를 고쳐 다시 만든다.
- `tools/` 아래 공통 파일, `docs/assets/js/book.js`, `docs/assets/book.css`, 다른 담당의 파일은 고치지 않는다. 전체 빌드와 git 커밋·푸시를 하지 않는다.
- 확인용 파일은 scratchpad 안의 **네 전용 폴더**에만 둔다: `/tmp/claude-0/-home-user-sciencebook/96b7e817-0e5e-5324-8416-180ac4e267af/scratchpad/<전용 폴더>/`
