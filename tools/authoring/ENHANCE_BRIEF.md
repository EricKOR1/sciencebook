# 단원 보강 작업 지시 — 그림·시뮬레이션 보충, 바로 확인, 중간·고난도 문항

너는 중학교부터 대학 1학년까지를 한 권으로 잇는 과학 교재 웹사이트 「한 권으로 잇는 과학」의 **보강 담당**이다. 저장소는 /home/user/sciencebook 이다.
이미 완성된 단원 원고(Markdown)를 처음부터 끝까지 **검수**하고, 학생이 개념을 정확히 이해하도록 세 가지를 보탠다.

독자의 요청은 이렇다: "개념 설명에 그림이 꼭 필요한 곳에 그림이 부족하다. 예를 들어 「날씨와 기후변화」에 오호츠크해 기단, 북태평양 기단 설명은 있는데 정확히 어디에 있는지 헷갈린다. 전체를 검수해서 그림이나 시뮬레이션이 필요한 곳에는 꼭 넣어 달라. 개념을 정확히 이해했는지 확인하는 단순한 예제를 더 넣고, 개념을 어디까지 활용할 수 있는지 알아보는 중간·고난도 문항도 넣어 달라."

담당 단원의 파일은 저장소에서 `{단원 id}_` 로 시작하는 `.md` 이다(예: `m3-02_날씨와_기후변화.md`, `3-4_운동량과_충격량.md`).

## 먼저 읽을 것
1. `tools/authoring/VISUALS_GUIDE.md` — 그림(SVG)·시뮬레이션 제작 규칙과 확인 방법 전체. 견본 파일도 읽는다.
2. `tools/authoring/WRITING_GUIDE.md` 4절(표기 규칙)과, 대학 단원(id가 u로 시작)이면 `tools/authoring/UNIV_GUIDE.md` 2절·7절.
3. 담당 단원 원고 전체, 그리고 이미 들어 있는 그림(`docs/assets/fig/{id}-*.svg`)과 시뮬레이션(원고의 `<!-- sim:… -->`).
4. 중·고등학교 단원이면 그 단원의 성취기준과 해설(원고 맨 위 상자, `tools/authoring/curriculum/`) — 새 문항도 **교육과정 범위 안**이어야 한다.

## A. 시각 자료 검수와 보충
STEP 2·STEP 3·탐구 활동의 **모든 소절**을 차례로 읽으며 이렇게 묻는다: "글과 표만 읽고 위치·모양·구조·과정·관계를 머릿속에 정확히 그릴 수 있는가?" 그릴 수 없으면 그림이 **꼭 필요한 곳**이다.

그림이 꼭 필요한 경우(이미 그림·시뮬레이션이 있으면 제외):
- **어디에 있는지·어떻게 퍼져 있는지**: 기단, 해류, 판의 경계, 지진대·화산대, 기압 배치, 태풍 경로, 기후대, 지질 분포, 천체의 위치 관계 → **지도·배치도**
- **생김새와 구조**: 기관·세포·분자·결정·실험 장치·기계·지층 단면·천체 내부
- **차례로 일어나는 과정**에서 모양이나 위치가 바뀌는 것(mermaid 도표는 상자와 화살표뿐이라 모양·위치를 보여 주지 못한다)
- **그래프로 보아야 하는 관계**: 본문이 글이나 표로만 설명한 비례·곡선 모양·시간에 따른 변화
- **실험 장치와 방법**, **힘·속도 벡터, 광선, 회로도**, **두 대상의 나란한 비교**
- 예제·문제가 그림 없이는 상황을 떠올리기 어려운 경우

기준과 분량:
- 꾸미기용 그림은 만들지 않는다. 반대로 "있으면 좋은" 수준이 아니라 **없으면 헷갈리는 곳은 빠짐없이** 넣는다. 단원마다 보통 **3~6개**가 새로 필요할 것이다(이미 충분한 단원은 2개 안팎).
- 파일 이름 `{단원 id}-{영문-설명}.svg`, 제목 `그림 {표시 번호}-{n} 제목`(번호는 기존 그림 뒤로 이어 붙이면 된다. 나중에 조율자가 순서대로 다시 매긴다).
- 표식 `<!-- fig:이름 -->` 은 그 그림이 필요한 설명 **바로 뒤**에 넣는다(한 줄 단독, 앞뒤 빈 줄).
- **시뮬레이션**은 직접 조작해야 이해되는 개념인데 아직 시뮬레이션이 없는 경우에만, 단원당 **0~1개** 새로 만든다(대학 단원은 이름이 `u-`로 시작. 다른 단원은 `ls docs/assets/js/sims/` 로 겹치지 않는 이름).

### 지도 그림 만들기 (정확한 해안선)
위치가 중요한 그림은 손으로 대충 그리지 말고 밑그림 도구를 쓴다. 사용법은 `tools/authoring/basemap.mjs` 맨 위 주석에 있다.
```
cd /home/user/sciencebook/tools
node authoring/basemap.mjs --bbox 100,18,160,62 --width 720 --height 600 \
     --points "서울:127,37.5;시베리아 기단:108,52;오호츠크해 기단:148,54" --graticule 10 --out <전용 폴더>/map.json
node authoring/basemap.mjs --world --center 150 --width 720 --height 380 --graticule 30 --out <전용 폴더>/world.json
```
- 결과 JSON 의 `land`(육지 path), `graticule`(경위선), `frame`(테두리), `points`(경위도 → 그림 좌표), `lines`(경로 path)를 읽어 SVG 를 조립한다(python 생성 스크립트 권장).
- 육지는 `fill:var(--fig-soft-green)` 같은 토큰 색, 바다는 `var(--fig-soft-blue)` 또는 `var(--fig-paper)`, `fill-rule:evenodd`. 글자는 13~15px.
- 기단·해류·판 경계의 **위치와 범위는 과학적으로 맞게**(경위도로 정한 뒤 `--points`, `--lines` 로 변환). 대략적 범위임을 설명(desc)에 "모식도"로 밝힌다.
- 지명·해역 이름은 우리나라 교과서 표기(동해, 황해(서해), 남해, 독도 등)를 쓴다.

## B. 바로 확인 (개념 직후의 쉬운 확인 문항)
STEP 3의 **번호 붙은 소절(### ①, ### ② …)마다 하나씩**, 그 소절의 맨 끝(다음 `###` 나 `---` 바로 앞)에 넣는다. 그 소절을 읽자마자 풀 수 있는 **쉬운 문항 2~4개**다.
```
#### ✔ 바로 확인

1. (O/X) 기단은 넓은 지역에 오래 머문 공기 덩어리이다.
2. 빈칸: 겨울철 우리나라에 영향을 주는 한랭 건조한 기단은 (    ) 기단이다.
3. 지구가 받는 태양 복사 에너지를 100이라 할 때 우주로 되돌아가는 양은 얼마인가?

<details>
<summary>정답</summary>

1. O
2. 시베리아 — 대륙에서 생겨 건조하고, 고위도라 차갑다.
3. 100 — 복사 평형이므로 받은 만큼 내보낸다.

</details>
```
- 형식을 그대로 지킨다(헤딩 `#### ✔ 바로 확인`, 번호 목록, `<summary>정답</summary>`, 빈 줄).
- 유형을 섞는다: O/X, 빈칸, 짝짓기, 고르기, 한 단계 계산, 그림·표 읽기. 그 소절의 **핵심 용어·정의·관계식·흔한 오개념**을 짚는다.
- 정답에는 한 줄 이유를 붙인다. 본문에 없는 내용을 묻지 않는다.

## C. 중간·고난도 문항 추가
`## ✅ 개념 확인 문제` 의 `### 융합·서술형` 뒤에 두 소제목을 **이 이름 그대로** 추가한다. 문항 번호는 기존 번호에 **이어서** 붙인다(기존 문항과 번호는 건드리지 않는다).
```
### 실력 다지기        ← 중간 난이도 3~4문항
### 도전              ← 고난도 2~3문항
```
- **실력 다지기(중간)**: 두 개념을 이어야 풀리는 문제, 자료·그래프·표를 해석하는 문제, 두 단계 계산, 까닭을 설명하는 문제.
- **도전(고난도)**: 여러 단계 추론, 처음 보는 상황에 개념 적용, 실험 설계나 결과의 오류 찾기, 자료 분석 뒤 서술, 조건을 바꾸면 결과가 어떻게 달라지는지 예측. 지식의 양이 아니라 **개념 활용의 깊이**로 어렵게 만든다.
  - 중·고등학교 단원: 성취기준과 해설의 **범위 안**에서 낸다(범위 밖 공식·용어 금지, STEP 5 내용 금지).
  - 대학 단원: 그 단원의 범위 안에서 종합 계산·유도·해석을 요구한다.
- 기존 문항과 소재·유형이 겹치지 않게 한다. 필요하면 문항에 표(Markdown)나 새 그림을 붙인다.
- 문항 형식은 기존과 같다: `**11.** …` 다음에 `<details><summary>정답 및 해설</summary>` (빈 줄 규칙 지킴). 해설은 풀이 단계를 보여 주고, 서술형·도전 문항에는 **채점 포인트**를 적는다.
- 수치가 나오는 문항은 모두 python으로 계산해 정답을 확인한다. 정답이 하나로 정해지는지 직접 풀어 본다.
