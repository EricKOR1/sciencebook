# 문항 그림 검토 작업 지시 — 새로 넣은 문항 그림의 정확성 확인

너는 중학교부터 대학 1학년까지를 한 권으로 잇는 과학 교재 「한 권으로 잇는 과학」의 **검토자**다. 저장소는 /home/user/sciencebook 이다.
다른 담당이 예제·바로 확인·개념 확인 문제에 새로 넣은 **문항 그림**(파일 이름에 `-q-` 가 들어 있는 SVG)을 비판적으로 확인하고, 잘못은 **직접 고친다**(해당 부분만, 최소 수정). 학생이 이 그림을 보고 문제를 풀므로, 그림이 문제와 어긋나거나 틀리면 반드시 잡아야 한다.

담당 단원의 파일은 저장소에서 `{단원 id}_` 로 시작하는 `.md` 이다.

## 검토 대상 찾기
```
cd /home/user/sciencebook
ls docs/assets/fig | grep "^<단원 id>-q-"                 # 새 문항 그림
grep -n "fig:<단원 id>-q-" <원고 파일>                      # 원고에서 넣은 자리
git diff e500cd4 HEAD -- <원고 파일> | grep "^[-+]" | grep -v "^[-+][-+]"   # 그림을 넣으며 고친 문항 글
```
그림마다 그 그림이 붙은 문항(문제 글, 정답·해설)을 함께 읽는다. 문항을 직접 풀어 본 뒤 그림을 본다.

## 확인할 것 (우선순위 순)
1. **문제와 일치하는가**: 그림의 수치·각도·길이 비·개수·눈금·방향·기호(A, B, (가), ㉠ …)가 문제 글·표·해설과 정확히 같은가. 그래프의 점·곡선은 SVG 좌표를 읽어 python으로 다시 계산해 대조한다(축 눈금 → 값 변환). 힘·속도 화살표의 길이가 크기에 비례하는가(아니면 "길이는 크기와 무관"이라고 적혀 있는가).
2. **정답을 드러내지 않는가**: 문제 쪽(`<details>` 밖)에 놓인 그림이 구해야 할 값·방향·이름을 보여 주지 않는가. 사이트는 SVG의 `<title>` 과 `<desc>` 를 그림 아래에 그대로 보여 주므로 **`<desc>` 글도 읽는다**(정답이 적혀 있으면 문제에 주어진 내용만 남긴다). 비율로 답이 읽히는 경우(구할 높이·거리를 실제 비율로 그린 경우)는 "모식도"로 바꾸거나 표시를 지운다. 정답·해설 안의 그림은 답을 보여도 된다.
3. **과학적으로 맞는가**: 방향과 위치를 특히 본다 — 오른손 법칙(전류·자기장·힘, ⊙·⊗), 공전·자전 방향과 속도 화살표, 하늘 그림의 동서(남쪽을 보면 왼쪽이 동), 배사(위로 볼록)·향사, 정단층·역단층의 상반, 북반구 전향력(바람의 오른쪽 직각)과 힘의 평형(합이 0), 고·저기압 주위의 바람, DNA 5′·3′ 과 상보 서열, 가계도 기호와 유전 양식, 염색체 수와 염색 분체, 심장의 좌우, 물관(안)·체관(밖), 전지의 극과 전자 이동, 입자 모형의 개수·전하 균형·원자 수 보존, 구조식의 원자가, 광선의 굴절 방향, 렌즈·거울의 상의 위치. 지도는 위치가 실제와 맞는지 경위도로 대조한다.
4. **문항 글**: 그림을 가리키는 말("그림과 같이" 등)이 자연스럽고, 그림의 기호와 문항의 기호가 같은가. 그림을 넣으며 고친 문장이 원래의 뜻·수치·정답을 바꾸지 않았는가(위 git diff 로 확인). 바로 확인 블록의 그림은 제목 바로 아래(목록 앞)에 있고 해당 문항이 "위 그림"으로 가리키는가.
5. **보기**: `cd tools && node figsheet.mjs <전용 폴더>/sheet.png light <id:그림이름> …` (6개 안팎씩; 접힌 해설 안의 그림도 펼쳐서 찍는다. 시간 초과가 나면 쪽별로 나눠 돌린다) 와 dark 로 한 번씩 본다. 글자 겹침·잘림(viewBox 밖), 지시선이 구조 밖을 가리키는 곳, 어두운 화면에서 안 보이거나 뜻이 뒤집히는 색을 고친다. 너무 크게 늘어나는 간단한 그림은 루트 `<svg>` 에 `class="fig-small"` 과 좁은 viewBox(너비 420~480)를 쓰는지 본다(없어도 오류는 아니다. 글자가 지나치게 커 보일 때만 고친다).
6. **형식**: 고친 뒤 `python3 tools/authoring/check_lesson.py --enhanced <담당 파일들>` 이 모두 OK, `cd tools && node build.mjs <담당 id들> && node qa.mjs <담당 id들>` 이 문제 없음.

SVG 를 고칠 때 주의: CSS 클래스 이름은 글자로 시작(숫자로 시작하면 스타일이 무시된다), 속성 이름·값에 유니코드 마이너스(−) 금지, 색은 토큰(`var(--fig-…)`)을 쓰되 색 자체가 뜻인 것은 고정색 + 테두리.

## 작업 원칙
- 최소 수정. 맞는 그림과 글은 건드리지 않는다. 문항 번호·정답을 바꾸지 않는다.
- 그림이 문제와 어긋나면 **그림을 문제에 맞춘다**(문제의 수치가 명백히 틀린 경우만 보고에 적고 문제는 두라).
- 그림이 정답을 피할 수 없이 드러내고 고칠 방법이 없으면 그 그림을 해설(`<details>`) 안으로 옮긴다(문항 글의 "그림과 같이"도 되돌린다).
- `tools/` 아래 공통 파일, `docs/assets/js/book.js`, `docs/assets/book.css`, 다른 담당의 파일은 고치지 않는다. 전체 빌드와 git 커밋·푸시를 하지 않는다.
- 확인용 파일은 scratchpad 안의 **네 전용 폴더**(작업 지시에 적힌 이름)에만 둔다:
  `/tmp/claude-0/-home-user-sciencebook/96b7e817-0e5e-5324-8416-180ac4e267af/scratchpad/<전용 폴더>/`
